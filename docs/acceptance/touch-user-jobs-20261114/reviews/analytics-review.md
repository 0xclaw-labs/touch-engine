## 发现

### P1：门店内容生成费用跨店泄漏且筛选说明错误

- 位置：`server/internal/store/store_dashboard_ops.go:741`、`:746`；`server/internal/httpapi/handlers_dashboard_ops.go:72`、`:82`；`web/src/components/work/analytics/analytics-view.tsx:454`。
- 可复现条件与步骤：组织 A/B 店各有已结算内容生成费用；以仅 A 店权限的店经理从工作台进入经营看板，查看内容生成费用，或选择 A 店后应用筛选。该金额仍包含同租户 B 店数据。
- 代码证据：费用 SQL 仅按 tenant、可选 campaign、时间过滤，不应用可信 scope 或 store_id；新增账单权限检查仅遮蔽 `cost_reconciliation`，未遮蔽 `cost.content_generation_amount_minor`。页面明确写费用支持门店维度。
- 影响：泄漏其他店费用，且经营者基于错误范围决策。已有代码推断；待以隔离的双店工程事实及正常浏览器入口确认，修复后复验原路径、API 与门店筛选。

### P1：带门店范围店员被统计读面误拒

- 位置：`server/internal/httpapi/handlers_dashboard_ops.go:26`、`:31`；`server/internal/httpapi/handlers_dashboard.go:40`；`server/internal/authz/authz_access.go:121`。
- 复现：在真实 HTTP 工程夹具中将店员成员设置为 A 店 `store_scope`，以店员请求统计。集成负责人红测观察到 `allowScopedList` 在 SQL 前返回 403 `out_of_scope`。
- 证据：两个统计端点均只有店经理显式设置查询 scope；目前在该授权门提前拒绝带范围店员。身份授权注释表明获授权的带 scope 店员应限定本店。此前仅凭静态代码推断跨店泄漏不成立，已纠正；本次已证实的现象是整个统计被误拒。
- 影响：合规店员无法读取本店事实。需依原权限裁决并同时限定两读面，修复后验本店可读、跨店拒绝及同会话撤权；正常浏览器仍待复验。

### P1：返回工作台链接指向 404

- 位置：`web/src/components/work/analytics/analytics-view.tsx:94`、`:139`；`web/src/app/work/` 没有 `page.tsx`；`web/src/app/page.tsx`。
- 复现：在候选 `3b37cc1` 的工程替身环境，浏览器经 `/admin` 表单使用 seed 账号登录；访问商家首页 `/`，点击“统计”可正常进入经营看板；点击新增“返回工作台”所指 `/work`，实际 Next 返回 404。
- 证据：新增的正常态和错误态“返回工作台”均指向不存在的 `/work`；此前从兼容 `/admin` 页面误判无统计入口，已改正；真实首页的统计入口可用。404 为实际浏览器结果。
- 影响：统计页返回链接无效；修复后需从真实入口点击进入并点击返回，分别在桌面和移动端复验。

### P2：部分缺失的已结算金额被展示为完整费用

- 位置：`server/internal/store/store_dashboard_ops.go:741`、`:746`；`server/internal/dashboard/funnel.go:756`；`web/src/components/work/analytics/analytics-view.tsx:455`。
- 可复现条件与步骤：同一范围、窗口有两笔已结算内容任务，其中一笔金额已知、一笔金额缺失；通过正常入口查看内容实际生成费用。
- 代码证据：SQL `COUNT(*)` 统计两笔，`SUM` 忽略空金额，仍返回已知部分之和；构建器仅依赖和是否非空标可用，页面直接标为实际生成费用及两次已结算。
- 影响：少报实际总费用，未知伪装成完整已知。待针对混合缺失、全部缺失、真实零的事实集独立复算并浏览器复验。
