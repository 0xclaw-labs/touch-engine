## Task 2 — 领域类型与确定性 Gate（纯函数层）
`server/internal/channeladmission/channeladmission.go`：
- 类型：Platform/EntryMode/Scenario/AdmissionStatus/CapState 常量；Record 结构体
  （身份键+能力+审计字段）；Machine reason codes（admission_unknown/not_admitted/
  admission_expired/wrong_binding/channel_closed/reward_play_not_authorized/missing_fields）。
- `Gate(in GateInput, r Record) Decision`：固定序裁决 closed → not_admitted →
  unknown → expired → wrong_binding(scope) → reward 玩法资格 → 放行+缺字段提示。
- `unknown` 永不 allowed；奖励玩法仅 admitted+reward_ok 放行。
- 测试（红→绿）：spec §Q5 矩阵 1-5、7-8 + 固定裁决序 + Record 校验
  （非法 status/entry_mode 拒绝）。
提交：纯函数层。

## Task 3 — 迁移 0026/0027 + store 读表
1. `0026_channel_admissions.sql`：主表，身份键 UNIQUE(platform,entry_mode,scenario,
   tenant_scope)，status CHECK 三态，能力列 TEXT(supported/unsupported/unknown)，
   审计列（reason_code/reason_text/official_sources TEXT/last_checked_at/valid_until/
   close_reason/seed_version）。
2. `0027_channel_admission_revisions.sql`：版本历史表（记录键、seed_version、payload
   sha256、action、at）；同载荷重复装载不追加（应用层判定）。
3. `store/store_channel_admission.go`：UpsertFromSeed（变更才写 revisions）、
   ListAdmissions(tenantScope…)、GetAdmission(platform,entry_mode,scenario,tenant)。
4. 测试（红→绿）：迁移可应用、装载幂等（二次装载 revisions 不增长）、租户作用域
   查询、库内记录与 JSON 种子一致性（装载后逐条比对）。
提交：迁移+store。

## Task 4 — httpapi 读路由 + Gate 接线（FEATURE_CHANNEL_ADMISSION 默认 off）
1. config.go：`EnvFeatureChannelAdmission = "FEATURE_CHANNEL_ADMISSION"`（默认 off，
   登记制注释对齐先例）。
2. `httpapi/handlers_channel_admission.go`：
   - `GET /api/v1/channel-admissions`（商家面，requireSession，按 X-Tenant-ID+
     tenant_scope="*" 合并，输出可选渠道+缺项原因）；
   - `GET /api/v1/public/links/{code}/channel-admission`（顾客/交接面，GET-only 白名单
     字段，platform/entry_mode 查询参数，输出当前可执行动作+缺字段提示）。
   - off = 路由不注册 + admissionGate 统一 404（双保险同 FEATURE_DASHBOARD）。
3. server.go：最小窄补丁注册段（`if s.Cfg.FeatureChannelAdmission { ... }`）。
4. 测试（红→绿）：off 时双 404；on 时商家面列表形状、公共面 allowed=空集+
   诚实缺项输出（种子全 unknown/not_admitted，无 admitted 路线）。
提交：读面。
