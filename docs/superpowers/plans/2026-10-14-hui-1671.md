# HUI-1671 真实奖励交付 Implementation Plan

**Goal:** 店员按活动允许的证据确认 → 真实发放可核销券/赠品/折扣 → 核销/更正，
全程真实 HTTP + SQLite，`tenant+participation+benefit_slot` 零重复发放。

**Architecture:** 新叶子包 `server/internal/rewardops`（判定 + 外部券接口）；
迁移 0023/0024/0025；`store_reward_ops.go` SQL 账本（事务 + 唯一约束 + append-only
流水）；`handlers_reward_ops.go` HTTP 面（管理面无开关、公共面 FEATURE_REWARD_OPS
默认 off、受信预留 internal 面）；`/work/rewards` 升级为真实管理页。

**Tech Stack:** Go 标准库 + modernc sqlite（`cd server && GOWORK=off go test ./...`、
`go vet ./...`）；Next.js 15 BFF（`npx vitest run`、`npm run build`）。

**Spec:** `docs/superpowers/specs/2026-10-14-hui-1671-design.md`

## Global Constraints

- 不改：`publishreward`、`rewardrule` 既有导出、`authz.go`、`/c/[code]`、参与表、
  work 共享 layout、G1/G2 页面。httpapi 注册与 config 只打最小窄补丁。
- 迁移只许 0023、0024、0025，additive，不动既有 CHECK/列。
- 证据三态；仅官方模式人工/自报永不满足；人工永不改写成 official。
- UNIQUE(tenant, participation, benefit_slot)；事件 dedup_key 部分唯一索引。
- 敏感券码不进 operations.payload、不进公共面、不进日志。
- 每任务先红后绿、小提交；Go 测试必须 `cd server && GOWORK=off go test ./...`，
  go vet 通过；web `npx vitest run` + `npm run build` 必须过。
- E2E harness（web/e2e/run.sh）端口 18460-18462：跑前 lsof 检查，被占则跳过并注明。
