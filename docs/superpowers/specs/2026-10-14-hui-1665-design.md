## 1. 领域增量（root 裁决 1：扩展既有标签域，独立别名，零第二套链接模型）

核心判断：PR#4 的标签是 `campaign_links` 的管理面包装，**多个 tag 共享一条 link** 时入口的启停/换绑是 link 级的——这正是票面要求复核的「停 tag 传播 link」根源。增量不修 link 语义（旧卡/旧码/旧页全兼容），而是在其上新增**按卡独立的稳定别名层**：

- `touchpoint_aliases`（迁移 0040）：一行 = 一张实体卡的固定入口。`code` 为服务端随机不透明别名（**复用 `campaign.NewShortcode` 生成**：Crockford base32、60 bit 熵、同一形状闸 `ValidShortcode`，alias 不可枚举）；`tag_id` UNIQUE（一标签一稳定入口，重复启用 409 `already_provisioned`）；`campaign_id` 是**当前目标活动**（服务端从标签绑定 link 派生初始值；换绑直接改此列）；`store_id/label/position` 位置标注（桌贴/收银台/立牌，自填文本）；`status`（active/disabled）是**该卡自己的开关**；`deployment_stage` 五态部署进度（§4）。
- `touchpoint_events`（迁移 0041）：created / rebind / status_change / stage_change 审计留痕（换绑审计 + 部署记录接收，票面「接收实际写入/回读记录」）。0042 **不使用**（预留位留空，本票两支迁移够用）。
- 实体卡写 **`<PUBLIC_BASE_URL>/t/{alias_code}`**：固定 HTTPS 入口，服务端解析当前活动。卡上只有不透明码 URL——无临时 share_id、无凭据、无顾客信息（结构保证：表里没有这些字段）。

**裁决理由**：换绑不改 URL 的唯一途径是「URL 指向稳定别名而非短码」；停用单卡不误停他卡要求开关挂在比 link 更细的粒度。别名层两条同时满足，且对既有五态模型零侵入。

## 2. /t/{code} 公共解析（root 裁决 6：NFC/QR 同解析；FEATURE 默认 off）

`GET /api/v1/public/touchpoints/{code}`（无会话、GET-only、白名单载荷）+ web 路由 `web/src/app/t/[code]/page.tsx`：

- **服务端解析顺序**：形状非法 / 未知码 / 别名停用 / 目标活动不存在 → 统一 404 单字段 `{state}`（`not_found` / `touchpoint_disabled`，防探测：形状错误与不存在不可区分）。别名 active → 取目标活动的**规范短码**（最早启用 link，否则最早 link）→ 返回 200 `{state, code}`（state 为该短码在当前时刻的五态）。
- **web /t 页**：FEATURE on 且拿到 `code` → `window.location.replace("/c/"+code)`（**临时跳转，绝无 301/308 永久缓存**；换绑/停用即时生效）。别名为 `not_found`/`touchpoint_disabled` → 本地极简 404 文案（不跳转、不泄漏存在性）。活动级非可用态（暂停/过期等）也交给既有 `/c` 页渲染——**1896 的公共呈现零重复**，且碰一碰后续链路（留资/参与/权益）在 /c 上原样可用。
- **FEATURE_TOUCHPOINT_ENTRY（默认 off）双保险**：off = Go 路由不注册 + handler gate 再答统一 404；web /t 页 server 侧读 `process.env` → `notFound()`。管理面端点不加开关（仓内惯例）。
- **缓存失效（root 裁决 5）**：`TouchpointRows`/`LoadTouchpointRows`/`DecideTouchpoint` 与 `ResolvedRows` 同构，状态在命中时刻现判（窗口绝不冻结进缓存条目）；别名建/停/换绑全部 `bumpEpoch` → 结构失效 0 陈旧请求；TTL 兜底沿既有 3s±1s 预算（同一 readcache 策略，无 Redis）。挂在 `FEATURE_PUBLIC_CACHE` 既有开关之下（缓存策略一处裁决）。
- PUBLIC_BASE_URL 缺失 → 触点 QR/CSV 端点 503 fail-closed（既有先例）；不生成占位域名二维码。

## 3. 管理面（root 裁决 2：/work/touchpoints 独占页；裁决 3 换绑；裁决 4 停用语义）

端点组 `/api/v1/touchpoints`（requireSession + `requireTagFace`：org_owner 全租户 / store_manager 本店、服务端强制 scope、跨租户 404 掩码——与 NFC 面同一矩阵）：

| 端点 | 语义 |
| --- | --- |
| `POST /touchpoints` | `{tag_id, position?, label?}` 为既有标签启用稳定入口：服务端从标签 link 派生初始活动，生成别名码；重复启用 409；他店/跨租户 404。 |
| `GET /touchpoints?store_id&campaign_id&status` | 列表（JOIN 出标签/门店/分组/目标活动标题 + 当前有效状态）。 |
| `GET /touchpoints/{id}` | 详情：五态部署进度 + 目标活动 + **检查**（= 公共解析同源计算，展示访客真实所见）+ 别名 URL。 |
| `POST /touchpoints/{id}/rebind-preview` | `{campaign_id}` → 当前→新活动预览 + 影响范围（`started_participations`：只读 COUNT 当前活动已开始参与数，3546 语义——这些参与继续绑定原活动，换绑不挪动）。目标活动必须本租户 + 本店 scope + 至少有一条短码（无入口活动 400）。 |
| `POST /touchpoints/{id}/rebind` | `{campaign_id, expected_campaign_id}` 乐观并发控制：当前活动 ≠ expected → 409 `rebind_conflict`（并发换绑显式失败，后到者重读预览）。同一事务写审计。 |
| `POST /touchpoints/{id}/status` | **只改别名自身**（绝不触碰 campaign_links）——单卡停用不误停共享 link 的其他卡（root 裁决 4 的「独立可控入口」分支）。 |
| `POST /touchpoints/{id}/stage` | 部署五态显式推进（§4）。 |
| `GET /touchpoints/{id}/qrcode` | `/t/{code}` PNG（qrentry 白名单尺寸；PUBLIC_BASE_URL 缺失 503 `qr_not_configured`）。 |
| `GET /touchpoints/export.csv` | 六列契约不变，`url` 列 = `/t/{alias}`；同样 503 fail-closed。 |

**停用语义复核的完整答案（root 裁决 4）**：
- 新路径（本票默认）：别名停用只关自己的 `/t` 入口；共享 link 的其他卡零影响。服务端与 UI 一致（列表/详情即所见）。
- 旧路径兼容：未启用别名的标签在**新页面**上停用时，UI 必须先展示共享影响（`GET /api/v1/nfc/tags` 视图已含 link 归属，前端按 link 分组统计 N 卡共享并要求显式确认）才调既有 `/nfc/tags/{id}/status`（旧行为=传播）。旧 `/admin` 页零改动零感知。「明确批量影响确认」分支成立。
- 旧 `SetTagStatus` 逐字节不动（/admin 只读兼容红线）；其传播语义在新页面上被别名路径替代，报告中如实记录双轨现状。

**换绑双轨**：别名路径换绑 = 改 `campaign_id`，URL 不变（票面「同卡换活动 URL 不变」）；旧路径（PATCH link_id）URL 会变，新页面在无别名标签上明确提示「旧路径换绑会改变印出 URL，建议先启用稳定入口」。

## 4. 部署五态（票面「标签详情清楚分开」）

`deployment_stage`：`registered`（已登记）→ `awaiting_write`（待写入）→ `written_awaiting_readback`（已写入待回读）→ `readback_done`（已回读）→ `device_verified`（真机打开验证）。

- **只经 `POST /stage` 显式推进**：服务端校验只能前进一格（跳级/倒退/未知值一律 409），每步带 `note` 留痕进 `touchpoint_events`。真实工具/人员证据归 HUI-1663 消费；本票只提供权威记录位。
- **CSV 下载、二维码下载、「检查」按钮零推进**（测试断言：导出/检查后 stage 不变；「写入未知状态不冒充已部署」）。UI 文案守卫进 vitest：未到 `device_verified` 不出现「已部署/已上线」表述。
- 批量创建出的标签一律 `registered`；无任何自动推进路径。

## 6. 安全与数据红线

- 别名码 = 服务端随机（同短码熵源），不可枚举、不嵌结构；管理面之外零别名级数据。
- 公共载荷白名单：`{state}` / `{state, code}`——无 uid_hint、无租户/主体/门店内部字段、无后台角色（测试断言形状与关键词）。
- 换绑目标只能本租户 + 本店 scope 内已登记活动；禁止任意外部 URL（表里没有 URL 字段，跳转目标恒为本系统 `/c/{code}`）；客户端 tenant 提权不可达（tenant 取自会话成员行，`expected_campaign_id` 只做并发控制不做鉴权）。
- CSV/QR 载荷：六列闭集 + 注入转义 + `=+-@` 防护原样；无凭证无顾客数据。
- `source=nfc` 仅作统计语义：本票不改 participation 语义；/t 解析不做任何「到店/碰触证明」输出。
