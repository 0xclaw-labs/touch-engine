## 1. 领域包与文件面（root 裁决 1）

- 新建叶子包 `server/internal/participation/**`：领域类型 + 状态机 + 凭据密码学 + `Service`（own SQL，注入 `*sql.DB`）。
- **裁决理由（自答）**：仓内惯例是纯领域包（`custpublish`/`leads` 无 SQL）+ `store/store_*.go` 承担 SQL；但本票独占文件面是 `participation/**`，且票面写明「参与内部表只由 G2 修改」——表的所有权是包级边界，不散落进共享 `store` 包。故 `participation.Service` 自持 SQL（同 `db` 包自持迁移的先例），httpapi 只经 `Server.Participation` 字段注入消费。
- httpapi 挂路由组 `/api/v1/participations`，沿用既有注入模式（`Server` 导出字段，如 `Matrix *matrixconsume.Consumer`；仓内并无名为 `Options` 的结构体，以导出字段注入为「现有模式」的实际形态）。
- web BFF：既有 catch-all 代理 `web/src/app/api/[...path]/route.ts` 已把 `/api/*` 透传到 Go `/api/v1/*`，参与路由**天然被代理**；web 侧新增 `src/lib/participation.ts`（视图类型 + 状态语义守卫）与 vitest 源码级断言（仓内惯例，node 环境无 DOM）。
- 不加第二套客户账户体系、不建消费者主库、不收集手机号。

## 2. 迁移（root 裁决 2，0020-0022 全部 additive）

- **0020_participations**：`participations` —— id、tenant_id/stores/campaigns 外键、link_code、touchpoint_source(nfc/qr/shorturl/manual)、rule_version、content_pack_version（预览期可换）、visitor_id（匿名续接键，随机非 PII）、status、idempotency_key、benefit_slot（传 G3 的稳定槽键，一参与一槽）、benefit_reservation_ref/state、starts_at/expires_at、时间戳。UNIQUE(tenant_id, campaign_id, idempotency_key) 承载幂等。
- **0021_participation_attempts**：`participation_attempts` —— attempt 级**冻结** content_pack_version + rule_version、platform、handoff_method(h5/platform_miniprogram/staff_view)、status(prepared/handed_off/completed/canceled)。
- **0022_handoff_credentials**：`handoff_credentials` —— token_hash（SHA-256，UNIQUE；明文永不落库）、purpose(customer_resume/staff_verify)、target_scope、expires_at、used_at（防重放）、revoked_at。
- 命名全 snake_case；TEXT 主键前缀随机 id（`pt_`/`pta_`/`phc_`），镜像 `store.newID` 惯例。

## 3. 状态语义（root 裁决 3）

参与状态机：`pending → in_progress → awaiting_review → fulfilled`，任意未终态可 `canceled`。

- pending：已开始、权益预留未确认。in_progress：首次交接（attempt handed_off）后。awaiting_review：店员凭据兑换核验开始。fulfilled：仅服务层 `MarkFulfilled`（G3/HUI-1671 接线后调用），本票**无 HTTP 路由**可置位；幂等且拒绝降级——晚到失败/回执乱序不改写已兑现。
- 证据、发布尝试、权益发放、核销分开存：本票三表只存参与 + 尝试 + 交接；权益账/核销归 HUI-1671。禁单一 success 布尔。

## 4. 幂等与恢复（root 裁决 4）

- 同一 `idempotency_key` 的开始请求重放回原记录（HTTP 200 + 原 id，非 201），绝不新行。
- 浏览（GET 公共页）不建参与；只有显式 `POST /api/v1/participations` 才建。
- 内容预览可换选（`PATCH .../content`，未交接自由换）；**真正交接时**把所选 content_pack_version 与当时 rule_version 冻结进 attempt。
- 换稿/换平台 = 新 attempt；benefit_slot 全参与唯一，新 attempt 不新增 slot（slot 只在调用 G3 预留时传递）。
- 同设备重复碰触恢复：`POST /api/v1/participations/lookup`（visitor cookie + link_code）优先返回未完参与，不开新记录。跨设备不承诺自动识别同一人。

## 5. G3 受信预留端口（root 裁决 5）

```go
type BenefitReserver interface {
    Reserve(ctx context.Context, ref ParticipationRef) (ReserveResult, error)
}
```

- 生产接线等 HUI-1671 合并后由 root 安排；本票 `Reserver` 为 nil 时参与照建、`benefit_reservation_state=pending`（never confirmed），**未确认预留不得向顾客返回「已保留」**——payload 只暴露 `benefit_reservation_state`，文案守卫进 web 层测试。
- 测试 stub 覆盖四态：成功（confirmed + ref）/ 缺货（out_of_stock）/ 超时（timeout）/ 冲突（conflict）。不写第二份库存表。

## 6. 交接凭据与权限（root 裁决 6）

- 凭据 token：128-bit 随机 + 校验位（`ptx_` + base64url(body) + '.' + base64url(SHA-256(body) 首字节)）；服务端只存 SHA-256 全 token 哈希。防枚举靠 128bit 熵；校验位让读端先拒错码。
- 短时（默认 10 分钟）、单用途（used_at 事务置位，重放负例）、可撤销（revoked_at）。
- 兑换负例矩阵：未知 token=404（不区分形状）、过期=410、已用=409、已撤销=409、目标 scope 不符=403、跨租户=404（不泄漏存在性）。
- 参与二维码 = 凭据的载体（payload 为规范 URL 串，PUBLIC_BASE_URL 配置驱动；未配置则不带 payload 字段）。**码 ≠ 发奖授权**：凭据只绑定参与身份，不触发发放。
- 公开读取走「自身会话（visitor cookie 绑定）+ 凭据」；顺序/裸 ID 无绑定一律 404/403，不存在匿名按 ID 探测面。
- 店员侧：必须商家会话 + `authz.ActionReadRecord` + 门店 scope（store_manager 仅本店，org_owner 全租户）；成员撤权（members.enabled）即失效——复用既有 authz 矩阵，零新权限体系。

## 7. H5 cookie 边界（root 裁决 7）

- 首方 cookie `touch_participation_visitor`（128-bit 随机、HttpOnly、SameSite=Lax）**只**在开始参与/凭据兑换时签发，用于同浏览器续接与 lookup。
- 不假设 cookie = 平台 open_id；平台身份只能由对应平台正式登录证明取得（本票不实现，留接口边界）。不收集手机号。

## 8. 重启持久化验收（root 裁决 8）

Go 测试起**真实** `httpapi.Server` + 临时 SQLite **文件**库：建参与 → 关闭库句柄（模拟杀进程）→ `db.Open` 同路径重开 → 新 Server → 凭据兑换/lookup 恢复**同一**参与 id。全程无 mock 内存态。

## 9. 私有数据与清理（root 裁决 9）

- 凭据明文只存在于响应体，服务端日志面（`withRequestLog` 仅 method/path/status/duration/masked who）天然不含 token；另加显式测试断言「日志输出中不出现凭据明文」。对外展示一律 `redact.MaskCode`。
- 到期清理：`Service.Cleanup(ctx, now)` 导出方法（删过期凭据、按保留窗匿名化已终态参与）+ `StartCleanupLoop` 桩（不引 Redis，调度归运维侧一行接线）；策略成文于本文 §9 与包注释。

## 10. FEATURE 开关（新增）

`FEATURE_PARTICIPATION`（默认 off）：off = 全部 `/api/v1/participations*` 路由不注册（404 不可见）+ handler 内二次 gate 统一 404（双保险，与 FEATURE_DASHBOARD 同写法）。测试宿主自开开关；不依赖 FEATURE_AGENCY 等其他开关。
