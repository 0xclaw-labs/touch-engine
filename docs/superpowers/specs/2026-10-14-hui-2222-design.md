## 1. 关键设计问题与裁决（现场核实 + root 代答）

### Q1 商家落地页：`/` 是否已指向今日工作台？

**现场事实**：`web/src/app/page.tsx` = `<TodayDesk />`（MerchantGate 登录门）。已登录 →
TodayBody（「今天」任务列表 + 下一步交接）；匿名 → Login（邮箱/密码表单）；组织选择/无权限/
错误态都由 MerchantGate 分相渲染。DECISIONS.md B6-4 已认定「根页改造」条件不触发（HUI-2628 r3）。

**裁决**：root 裁决 1 的「若未指向才改造」条件不触发 → **零页面改造**，只做正向验证 + 补
E2E 证据（匿名 `/` 落登录页、已登录 `/` 落今日台）。今日工作台布局归 HUI-2628，本票不重排。

### Q2 「确认与核销」入口：开关、槽位、角色集、目标路由

**裁决（root 裁决 2）**：登记制开关 `FEATURE_SERVICE_DESK` 默认 off：
- off：入口不渲染；`/work/service` 路由不存在（Next 无该目录，天然 404）；
- on：入口渲染，href=`/work/service`；页面本体由 HUI-3562 同期开发，404 归 3562 补齐，
  两票互不阻塞。

**开关暴露缝**：web 现无任何 feature flag 读取机制（全仓 grep 仅 NEXT_PUBLIC_LEADS_ORIGIN）。
走仓内惯例把开关放 Go config（`EnvFeatureServiceDesk`，默认 off），由 `GET /api/v1/whoami`
响应新增 `features: {"service_desk": bool}`（恒存在，不随开关缺省）。选 whoami 的理由：
session 建立时必经（MerchantGate.confirmTenant 已解析 role/enabled/tenant_name），零新增路由、
零新增往返；e2e 可用 server env 直接翻开关。

**角色集**：`org_owner / store_manager / staff` 可见，agent（代运营只读）不可见。
依据 = server/internal/authz/authz.go 的 ActionUpdate 矩阵（org_owner 恒可、staff T0 语义、
store_manager 本门店、agent 写动作白名单外）——入口可见性对齐服务端真实核销权限，不发明第四套角色语义。

**槽位（最小窄补丁）**：两处既有 tk-nav 列表，均为本票独占文件面：
1. `web/src/components/work/work-frame.tsx`（/work/* 共享导航，由 work/layout WorkShell 传入开关与角色）；
2. `web/src/components/work/today-desk.tsx`（根页 `/` 自带同名导航，TodayBody 已持有 session）。

纯判定函数收口 `web/src/lib/work/service-desk.ts`：`serviceDeskEntryVisible(features, role)`，
两个槽位共用，不复制判断。

### Q3 生态菜单注册：真源与 vendored 副本

**现场事实（2026-10-14 实读）**：
- public-ai `docs/contracts/app-registry/v1/touchleads-manifest.json`：`app_id=touch-engine`、
  `enabled:false`、`menu_visible:false`、launch target `ti-touch-engine-web` →
  `https://touch-engine.example.invalid/admin`（占位 .invalid 域名 + 旧 /admin 路径）。
- public-ai `production-manifest.json` blob = `15573a95`，与 touch-engine vendored 副本
  （web/src/lib/eco-nav/registry/SOURCE.txt pin）逐字节一致 → **touch-engine 侧零改动**
  （不虚构未合并的值；touch-engine 不是自己 EcoTopNav 的登记行）。

**裁决（root 裁决 3）**：public-ai 开窄 PR（分支 `ext/hui-2222-touch-entry`）对齐可裁决的增量：
`enabled:true`、`menu_visible:true`、launch target 路径 `/`（今日工作台，非 /admin）、
沿用 HUI-2228 稳定 `app_id=touch-engine` 与 `target_id=ti-touch-engine-web`。
**域名不虚构**：host 保持现登记值不动，PR 正文与报告如实写「生产域名待 HUI-3531 联验确认」。
**PR 永不合并**（生产启用裁决归 3531）；touch-engine 侧 vendored 副本不同步该未合并内容。

### Q4 受控登录链验证（本地 VERIFIED 层）

**裁决（root 裁决 4）**：用 web/e2e 自含 harness（identity stub :18461 + go :18460 + next :18462，
`run.sh` 已编排）跑正向链。harness 身份 stub 接受任意 email/password、login 不创建成员关系
（handlers_auth.go 显式注释），因此四象限都能在本地真实验证：

| 场景 | 种子/操作 | 断言 |
| --- | --- | --- |
| 已登录 | owner@e2e.test → `/` | 「今天」今日台 + 种子活动项 |
| 匿名 | 清会话 → `/` | 登录表单（不泄露任何组织数据） |
| 多组织 | 新 seed：principal 双成员关系（A=staff、B=org_owner） | 组织选择器（只列名称，无租户编号输入）；选中 A → 今日台 |
| 无权限 | nobody@e2e.test（0 成员关系）登录 | 「当前账号没有可进入的组织。」（不让手填 tenant_id） |
| 会话过期 | 登录后清 cookie → `/` | 回登录页；重新登录可恢复 |
| 切组织清理 | 多组织用户改 localStorage 记忆 → 重载 | 组织名切换；上一组织活动标题不残留 |
| 切应用不建活动 | EcoTopNav 应用切换（provisional provenance） | 活动计数不变（commitTenantSwitch 拒绝非 public_ai_context） |

证据落 `docs/evidence/hui-2222/`（关键截图入库）。

### Q5 切组织/退出/撤权清理：缺什么补什么的最小面

**现场核实**：切换清理（applyMerchantSwitch）、记忆只写命中启用成员（writeTenantMemory）、
撤权=whoami 403 → decideTenantConfirm reject → 文案「没有读到当前组织。没有沿用上一户的数据。」
均已存在且有 vitest（workspace-tenant/touch-shell）。任意 query/return_url 不提权由
memberships 端点忽略 header/query + allowlist emittable（.invalid/loopback/端口不输出）守门。
**裁决**：不重写身份系统；本轮只补「正向链」E2E 回归证明。发现缺口才最小补（执行中记录）。

### Q6 旧路径兼容

- `/admin` 书签：页面存在（helpers.login 即走 /admin），不动；E2E 回归断言登录后可用。
- `/c/{code}` 与既有公共路径：无 EcoTopNav 硬红线（spec 05 既有断言），本票零触碰
  `web/src/app/c/**`（HUI-1896 独占），全量 vitest + E2E 回归防误伤。

### Q7 验证分级口径（报告必须用此口径，不冒充）

- **Engineering = VERIFIED**：`cd server && GOWORK=off go vet ./... && go test ./...`；
  `cd web && npx vitest run`；`npm run build`。
- **Browser = VERIFIED / NOT_RUN**：本地 harness（18460-18462，lsof 被占则跳过并注明）；
  identity stub 属本地测试身份，不冒充真实 SSO。
- **Production = NOT_VERIFIED**：真实 HTTPS 域名、真实 SSO/audience、品牌可见性、
  public-ai 生产启用——生产配置改动未获授权，正向验收保留给 HUI-3531。
- 「正在建设」不掩盖服务错误；目标未核实不默认放行（开关默认 off 即此语义的落地）。
