## 1. 关键设计问题与裁决（root 代答，本代理复核通过）

### Q1 领域包放哪？是否复用 HUI-2251？
**裁决**：新建叶子包 `server/internal/channeladmission`。复用 HUI-2251 动作能力定义的
**思路**（platform + entry_mode + scenario + app_binding + tenant_scope 的正交维度、
unknown≠allowed 的 fail-closed 纪律），不 import 其他生态仓——本仓无该包实体，按票面
字段自建。不新建第二个生态 App Registry：本包只表达 Touch 增量维度，不自建平台身份体系。

仓内同型先例：`campaignrules`（纯确定性评估器 + 机器原因码 + 服务端单点判定）。
本包同纪律：`unknown` 永不等价 `allowed`；评估器纯函数，HTTP 层零业务判断。

### Q2 数据模型长什么样？
**裁决**：渠道准入记录 =
- 身份键：`platform`（douyin/xiaohongshu/bilibili/kuaishou/...）+ `entry_mode`
  （h5/miniapp/native/manual）+ `scenario`（如 store_promo / reward_task）+
  `app_binding`（platform_app / merchant_authorized / none）+ `tenant_scope`
  （"*" 平台级真值 / 具体租户）。
- 能力字段：媒体带入 / 标题 / 正文 / 话题 / POI / 回执 / 回调（supported / unsupported /
  unknown 三态，unknown 不默认没有也不默认允许）。
- 准入状态：`admitted` / `not_admitted` / `unknown`。
- 审计字段：拒绝或缺项原因（机器码+人话）、官方依据 URL、`last_checked_at`、
  `valid_until`、`close_reason`。

**迁移**：`0026_channel_admissions.sql`（主表，additive SQLite）；`0027_channel_admission_revisions.sql`
（版本历史表，**启用**——理由：票面要求「登记实际读取日期」且未来平台批复把 unknown→admitted
时必须有据可查的审计行；git 里的 JSON 种子是真源，revisions 表记录每次装载/变更的
seed_version+payload 指纹，同载荷重复装载不追加）。`unknown` 在类型与 CHECK 双层保证
永不等价 `allowed`。

### Q3 种子真值放哪、怎么装载？
**裁决**（仓内先例 = HUI-2227 vendored truth）：
- 契约真源：`docs/contracts/channel-admission/v1/seed.json`（版本化入库）。
- 装载：**启动装载**（比 migration INSERT 更自然——本仓迁移全是纯 DDL，且种子随契约
  版本演进）。Go 包 `go:embed` 自己目录下的 vendored 副本
  `server/internal/channeladmission/seed/v1/seed.json`，测试断言与契约文件**逐字节一致**，
  杜绝漂移。
- 种子条目（2026-10-14 官方调研结论，直接采用票面，逐条带官方 URL + 核查日期）：

| platform | entry_mode | scenario | 状态 | 依据要点 |
|---|---|---|---|---|
| douyin | h5 | store_promo（商铺宣传/营销内容） | **not_admitted** | 抖音发布能力使用规范明确排除商铺宣传、商品介绍等营销内容；普通 H5 能传视频≠本场景获准 |
| douyin | miniapp | reward_task（拍抖音/任务换奖励） | **unknown** | 基础发布与任务查询/状态推送是不同能力，任务需申请；未获批复前不得用于奖励玩法 |
| xiaohongshu | miniapp | store_promo | **unknown** | 小红书发小红书组件存在（媒体/标题/正文/话题/回调入口）；外部拉起、回调权限、激励规则未确认——不默认没有回调，也不默认允许 |
| bilibili | h5 | store_promo | **unknown** | 开放平台存在认证/应用/授权接入 ≠ 外部 H5 可带入手机发布页；不得编造 deep link |
| kuaishou | native | store_promo | **unknown** | Android SDK 能打开单视频发布页但属移动应用路线；话题携带另有限制；不能推定 H5 可用 |

其余平台（channels 等）留同一机制扩展位，v1 不要求穷举。

### Q4 读 API 与服务端强制点怎么交付？
**裁决**：三个消费面 + 一个强制闸，全部读端点走 `FEATURE_CHANNEL_ADMISSION`（默认 off =
路由不注册 + handler gate 统一 404，双保险，同 FEATURE_DASHBOARD 写法）：
- a) **商家面**（HUI-1676 消费）：`GET /api/v1/channel-admissions`——按租户/活动返回
  可选渠道与缺项原因（商家能看见被禁用原因及所需材料）。
- b) **顾客/交接面**（HUI-1670/1896 消费）：`GET /api/v1/public/links/{code}/channel-admission?platform=&entry_mode=`——按 platform+entry_mode+设备环境返回当前可执行动作与缺字段提示（顾客只看真正开放的路径）。
- c) **服务端强制点**：`channeladmission.Gate(...)` 校验函数（票面 `ProvideHandoffGate`
  语义）——platform+entry_mode+scenario+tenant+now 五元组确定性裁决，1670 交接前必须
  过此闸，前端隐藏按钮不算数。渠道 `closed` 后停止新交接；既有参与保留状态与履约处理
  入口（语义文档化于包注释，执行归 1670）。
- 本票只交闸与读路由，不改动 1670 发布适配器/1896 公共页/1676 活动表单（禁区）。

### Q5 测试矩阵锁什么？
**裁决**（逐条红→绿）：
1. `unknown` ≠ `allowed`（三渠道 unknown 全拒，原因码区分）；
2. `not_admitted` 拒绝（抖音普通 H5 营销场景）；
3. 准入过期拒绝（`valid_until < now` → `admission_expired`）；
4. 错 app/tenant 拒绝（tenant_scope 不匹配 → `wrong_binding`）；
5. 种子真值逐条锁定（五条 2026-10-14 结论 + 官方 URL + 核查日期）；
6. JSON 种子（vendored 副本 vs 契约文件）逐字节一致；
7. 渠道关闭后 `Gate` 拒新交接且返回既有参与保留语义的原因码；
8. unknown 状态下奖励玩法不可启用（同平台技术可用但玩法未获准 → 拒）。
