## 0. 本票范围声明（相对 PR#15）

PR#15（44ce4bd）的「预览 / 合规导出 / 手动发布」基线**原样保留、未重做**：`CustomerPublish` 组件与其能力矩阵面不动（挂载测试断言其在案）。本票只做票面新增量——**真实渠道交接与恢复**：渠道闸门裁决 → 内容快照确认（指纹绑定）→ 开始交接（attempt 冻结 + 受控媒体 + 恢复凭据）→ 九态状态机（证据来源强制）→ 三事实分别落库（人工永不转官方）→ 官方回执服务端验签。

## 1. 交付面

### 领域包 `server/internal/publishhandoff/**`（本票独占，交接表只由本包修改）
- `handoff.go`：九态状态机（previewed / handoff_preparing / handoff_ready / editor_opened / submitting / awaiting_review / platform_confirmed / canceled / failed / unknown）。每条边强制携带证据来源（`CheckTransition` = 结构边 + 证据闸双重）：`editor_opened` 只接受 verifier_proof（窗口失焦/点击/自报一律 422 evidence_required）；`platform_confirmed` 只接受 official_receipt（`requiredEvidence` 排除 staff_observation/staff_verification——**人工事实永不转官方**）；unknown 不允许重新 submitting（防盲目重投）。
- `adapter.go`：渠道适配纯函数。`PlanRoute` 消费 3535 的 `channeladmission.Record`（只 import 不改）：
  - **refused**（not_admitted / channel_closed / admission_expired / entry_not_configured）：诚实拒绝，**不携带手动指引**——手工路径不是被禁营销玩法的后门（拒绝面连内容快照都不泄露，gate-first）；
  - **manual_only**（admission_unknown，unknown ≠ allowed）：合规导出 + 手动步骤 + 交接/恢复/核验/幂等管线保持存活；
  - **automated**（admitted）：h5 深链或小程序薄路由；media/title/body/topic/poi 逐字段按官方能力格（CapSupported 才带入），不支持的字段交接前给出解释，不承诺全部预填。
- `receipt.go`：官方回执验签。HMAC 域分离（`publishhandoff/official-receipt/v1`）；**空密钥拒绝一切**（生产未配置 secret = 全部 NOT_VERIFIED，不伪报）；五绑定核对（app / tenant / participation / attempt / content_version，租户真值取自库行而非回执声明）；outcome 白名单（只有 published 确认）。
- `service.go`：全部行为——gate-first Start（拒绝先于内容探测）、幂等重放（同参与同平台回原行、不发第二份凭据）、冻结 attempt 校验（status=handed_off）、内容指纹确认（`ContentFingerprint`=标题+正文+话题+门店+媒体 sha256；换稿=新指纹=必须重新确认，422 confirmation_mismatch）、受控媒体铸造（HMAC 签名 URL + TTL + content-type 白名单；**文件字节零过本服务**；失败即 failed 且不触发任何生成）、顾客 done（仅事件不改状态）、Cancel、staff 事实两分落库（staff_saw_submit / staff_verified_work → awaiting_review）、ApplyReceipt（验签→绑定→重放去重（只对 official_confirmed 事件）→终态拒绝→结果核对→迁移）、超时→unknown→查询计数（Resend 拒绝：query_required）、弱网重试（从冻结快照重铸媒体）、重启恢复（卡在 preparing → ready，幂等）。
- `structural_test.go`：**结构性无外联保证**——包内非测试源码出现 net/http、os/exec、copyjob、publishreward、rewardrule、rewardops 任一 import 即 FAIL（交接失败不可能触发付费生成的编译期保证）。

### 迁移 0034-0035（additive，SQLite，纯 DDL）
- `0034_publish_handoffs`：九态 CHECK、evidence_source 非空 CHECK、UNIQUE(tenant_id, idempotency_key)、media/text 冻结快照、FK 到 participations/participation_attempts。
- `0035_publish_handoff_events`：append-only 事实事件（kind 白名单：state_changed / customer_done_requested / staff_saw_submit / staff_verified_work / official_confirmed / editor_open_proved / receipt_rejected / canceled）；部分唯一索引只在 `kind='official_confirmed'` 上对 receipt_id 去重——被拒回执可重评，已确认回执不可重放。
- 3546 attempt 状态机零改动（复用 prepared/handed_off 语义，发布结果态归本票域）。

### HTTP 面（`FEATURE_PUBLISH_HANDOFF` 默认 off；off = 路由不注册 404 不可见 + handler gate 统一 404 双保险）
- 顾客面（visitor cookie 作用域，他人一律 404 防枚举）：`GET .../publish-handoff/routes?platform=&with_snapshot=1`（只读裁决面 + 确认面快照指纹；**refused 平台不泄快照**，与 start 的 gate-first 一致）、`POST .../publish-handoff`（开始；幂等；422 refused/confirmation_required/confirmation_mismatch 区分）、`GET .../{id}`、`POST .../{id}/cancel|done|editor-opened`（editor-opened 无可验证证据一律 422）。
- 回调面：`POST /api/v1/public/publish-receipts/{id}`（服务端验签；验真但被拒返回 200 accepted:false 照录事件停止重试；未验真不落 receipt_id——防伪造者抢占真实回执号）。
- 店员面：`POST /api/v1/publish-handoffs/{id}/staff-events`（requireSession + authz.ActionReadRecord 门店作用域双 fail-closed；kind 白名单两分事实）。
- config.go 最小窄补丁：`FEATURE_PUBLISH_HANDOFF` 开关 + 五个 fail-closed 配置（media 基址默认 BFF 形 `/api/media-handoffs`、回执验签密钥（空=拒一切）、app_ref、H5/小程序入口基）；媒体签名复用 InternalToken（contentpack 交接同一密钥纪律）。

### web 层（自足组件目录 + 窄补丁挂载）
- `web/src/components/publish/state.ts`：文案纪律唯一出口——九态 fail-closed；**只有 platform_confirmed 的文案出现「已发布」**；awaiting_review/unknown/超时全部明示「不是发布成功」；`manualStepsFor` 对 refused 一律丢弃手动指引（即使服务端异常返回）；入口 URL（h5 只收 https 直达、miniapp 只收站内路径）与媒体地址（/api/ 相对或 https）形状闸；3546 恢复二维码载荷形状校验。
- `web/src/components/publish/PublishHandoff.tsx`：自足组件（只依赖 react + ./state）。路线预览 → 快照确认（指纹绑定）→ 开始交接 → 入口打开/媒体清单（只渲染文件名，带签名 URL 不进 DOM）→ 恢复方式一次性展示（含换设备入口）→ 我已完成（仅核验请求）→ 取消 → 刷新查询（unknown 只查询不重发）。开关关闭时整体 return null（页面布局不变）。不触碰奖励面（不发 publish-reward/reward-proof/self-report 请求，源码断言在案）；恢复凭据绝不写 localStorage。
- 挂载：`web/src/app/c/[code]/public-campaign.tsx` **2 行窄补丁**（1 import + 1 JSX，≤10 行红线）。BFF catch-all 零改动天然透传。

## 3. 票面实现要求逐项状态（11 项）

1. ✅ 预览+选平台+确认才建交接：routes 预览面（with_snapshot 指纹）→ 显式确认 → start 校验指纹与冻结快照一致（422 confirmation_mismatch 拒旧稿）；media/title/body/topic/poi 逐字段按 3535 能力格传递，不支持字段交接前解释（adapter 测试七场景）。
2. ✅ 按 3535 放行选择承接方式（h5 深链 / 小程序薄路由 / manual）；薄适配只消费 Touch 活动与参与权威（结构测试禁本包外联）；顾客无需安装任何 App（H5/小程序入口）。
3. ✅ 平台差异如实：douyin h5 not_admitted=拒绝（无手动后门）；xiaohongshu miniapp admitted fixture=automated；bilibili 未登记=unknown→manual_only（永不显示「已支持」）；快手原生 SDK 不推定（seed 中无 h5 admitted 记录即不可用）。真值全部读 3535 vendored seed，不要求开发者翻聊天。
4. ◐ 媒体按受控下载地址准备（HMAC 签名 + TTL + content-type 白名单 + 弱网重铸 + URL 形状闸）；**「实际可读性/时长校验」与「加载进度条」未做**：文件字节零过本服务是红线决定，可读性检查属媒体网关职责——残差 R1。
5. ✅ 交接不触发付费生成（结构性：禁 copyjob/publishreward import 测试 + 媒体失败即 failed）；换稿=新指纹=重新确认；换账号维度留待 1671 奖励面（残差 R5）。
6. ✅ 未实现任何平台授权调用 = 不可能用模拟器/协议破解/群控；客户端零 secret（mount 测试断言组件无 InternalToken/RECEIPT_SECRET 字样）；最终发布动作由用户在平台完成。
7. ✅ 九态状态机全落地；窗口失焦（422 evidence_required 实测）、网页点击、自报（done 仅事件）都不证明平台已打开/已发布。
8. ✅ 回执服务端 HMAC 验签 + 五绑定 + 伪造拒绝 + 重放幂等 + 乱序/终态拒绝 + 超时先回查（query_required，不盲目重投）。
9. ✅ 无自动回跳不阻止兑奖：离开前已有 3546 参与记录 + 短时单用途恢复凭据（token 一次展示 + 形状校验后的换设备入口）；unknown 不阻断（独立状态、继续查询）；店员可按 3546 参与码核验。
10. ✅ 三事实分别落库（staff_saw_submit / staff_verified_work / official_confirmed 独立事件）；人工永不转官方（requiredEvidence 结构排除）；取消/我已完成零奖励路径（包内无 rewardops）。
11. ◐ 下一步明确：资格关闭/过期/未准入=拒绝+官方来源解释；承接未知=合规导出+手动指引；弱网=重铸重试；失败/取消=可重开且不触发生成。**「未安装/旧版本/系统拦截/审核中」属平台 App 内场景**，本票无 App 客户端载体——残差 R4。手工导出只在 manual_only 提供，refused 无（无后门）。

## 5. 残差清单（诚实声明）

- **R1 NOT_VERIFIED**：真实手机 + 获准渠道端到端（票面验收 1）。红线内不可做；需 3535 放行路线 + 真实平台资格后另行取证。
- **R2 NOT_VERIFIED**：生产回执验签未配置——`PUBLISH_HANDOFF_RECEIPT_SECRET` 为空时验签器拒绝一切（fail-closed，不伪报）；上线前必须配置。
- **R3 残缺**：媒体「实际可读性/格式/时长校验」与「加载进度显示」未实现；受控媒体服务路由（/api/media-handoffs/*）未挂（URL 为契约占位，字节零过本服务；组件只渲染文件名，无死链暴露）。
- **R4 残缺**：平台 App 内场景（未安装/旧版本/系统拦截/审核中）无载体验证——本票只有 H5/小程序入口面；小程序薄路由的生产资格随平台申请进度。
- **R5 留给 1671**：换账号确认维度、人工先兑奖/官方晚到的重复发放裁决规则。三事实账本已就绪。
- **R6 依赖开关**：顾客面开始交接依赖 `FEATURE_PARTICIPATION`（参与记录）与 `FEATURE_PUBLISH_HANDOFF` 同时 on；本票未改动 participation 包。
